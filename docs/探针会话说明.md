# 实机探针会话说明

## 一句话

探针在**进游戏之前就装好**，之后保持静默，等你真正进关卡打起来才会记录。
**这次有两种模式，其中一种会真的改变游戏行为**——等于是一个可以上手玩的原型。

## 操作步骤

### 1. 让我启动并注入

```powershell
# 观察模式（默认）：只记录，不改任何行为
& .\tools\probe_session.ps1

# 免耗精模式：把格挡的精力消耗清零 —— 这是 MOD 第一个功能的可玩原型
& .\tools\probe_session.ps1 -Mode freeguard
```

**建议先跑 `freeguard`。** 理由：它同时完成两件事——
① 确认锚点找对了（格挡不再掉精力 = 判定点正确）；
② 让你直接体验 MOD 的核心功能。如果格挡依然掉精力，说明锚点错了，我会用观察模式的日志回头修正。

### 2. 然后正常玩，按顺序做 7 个动作

每个动作间隔 **2–3 秒**，日志就能按时间轴切段：

| 步骤 | 动作 | 目的 |
| --- | --- | --- |
| ① | 进关卡，站着不动 5 秒 | 基线 |
| ② | 空挥攻击 5 次 | 攻击耗精走哪条路径 |
| ③ | 让敌人打你，**不防御** | 未格挡受击基线 |
| ④ | **按住防御**让敌人打 5 次 | **格挡路径** ← 关键 |
| ⑤ | **精防**（快打到你时短按防御）几次 | **精防路径** ← 最关键 |
| ⑥ | 再站定 5 秒 | 收尾基线 |

> `freeguard` 模式下请注意看：**④ 的时候精力条是否几乎不动**。

### 3. 玩完告诉我

我跑汇总：

```powershell
python .\tools\summarize_probe.py `
  .\_work\probe.log
```

输出：每个目标的命中次数、线程分布、**直接调用方 TOP-N**、参数样本，
外加三条内存曲线（玩家对象、格挡资源表项、精力槽）。

## 这次装了什么，为什么

### 4 个断点

| 目标 | RVA | 是什么 |
| --- | --- | --- |
| t1 | `0x74DD09` | 写"本次攻击被格挡"标志位（分支一） |
| t2 | `0x74DD92` | 同一函数里的另一条格挡分支 |
| t3 | `0x74DE51` | **格挡扣精的那次调用**（`call 0x7B4C40`，`xmm1` = 消耗量） |
| t4 | `0x7B4C40` | 通用浮点扣减原语，用来看全游戏的精力消耗 |

`freeguard` 模式会在 **t3** 处把 `xmm1` 置 0 —— 扣减变成 `-0`，等价于免耗精。
**这不修改任何代码字节**，只是改被保存的线程上下文（上一轮已本地验证过这个机制）。

### 3 条内存监视器

| 监视 | 指针链 | 期望 |
| --- | --- | --- |
| `player_slot0` | `[0x18A0490]` | 进关卡后从 NULL 变为有效指针 |
| `guard_res7` | `[player+0x240] → +0xBA8(内联) → +0x238`，16 字节 | **格挡资源的当前值 / 消耗量**（float） |
| `gauge40` | `[player+0x240] → +0x40(内联)`，16 字节 | `Player::RecoverStamina` 用的 (当前, 上限) |

`guard_res7` 是最有价值的一条：**格挡时它应该掉，`freeguard` 模式下应该不掉**。
这是对锚点最直接的判定。

## 本次的推理链（为什么锁定这几个地址）

1. `Refer::IsAttackGuard` 节点 → `0x6ED140` → `0x6E58E0`，最终读取
   **`[[对象+0x90]+0xC8]` 这个字节标志** —— 这就是"本次攻击是否被格挡"。
2. 扫描全二进制 18MB 代码，写 `byte [reg+0xC8] = 1` 的指令**只有 4 条、3 个函数**。
   其中 `0x749640` **正是上一轮独立推断出的首选锚点候选**
   （同时满足：调玩家访问器、用 `+0x240`、调精力扣减原语）。**两条独立证据线收敛。**
3. 在同一函数里紧跟其后就是格挡扣精：
   `[[char+0x240]+0xBA8]` 资源表 → 索引 7 → `xmm1 = [entry+0x10] × 0.2` → `call 0x7B4C40`。
   系数常量 `0x1588828` 实测 = **0.2f**，即"格挡消耗 = 攻击精力伤害 × 20%"，符合仁王设计。
4. `0x749640` 只有 **1 个调用者**：`0x6FE5B0`（命中结算分发器）。

## 如果结果不对

| 现象 | 含义 | 我会怎么做 |
| --- | --- | --- |
| 日志完全没有 `PROBE begin` | 注入失败 | 重跑脚本 |
| 四条监视器全无记录 | 还在标题画面 | 需要进关卡 |
| `player_slot0` 有值，但 4 个断点全零 | 格挡不走这条路径 | 换候选：`0xD68150`、`0x10242F0`（另外两个写标志位的函数） |
| `freeguard` 下精力照掉 | t3 不是真正的扣精点 | 用 t4（通用扣减原语）的调用链反查真正的扣减点 |
| `guard_res7` 是乱码浮点 | 偏移推错 | 用 `gauge40` 对照，重新推索引 7 的地址 |
